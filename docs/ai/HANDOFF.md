### Journey Desk v2B — Map Coordinate Contract foundation (merged, PR #472)

Persists **real** coordinates where source data already has them, so a later v2C can plot real pins. **Frontend-only; no SQL/schema change (the `details` JSON carries coordinates); no new geocoding, providers, or fake positions.**
- **Normalizer** (`lib/itineraryCoordinates.ts` `extractItineraryCoordinates(source)`): returns `{lat,lng}` or `null`. Reads only real shapes — `lat/lng`, `latitude/longitude`, `location.{lat,lng}`, `geometry.location.{lat,lng}` (Google) — accepts numbers or safely-parseable numeric strings, **range-validates** (lat −90..90, lng −180..180), and rejects the **(0,0) null-island** placeholder. No network, no index/destination/address/maps-URL inference, no `goldenSpread`.
- **Audit + write status by flow:** Explore restaurant/attraction add (×4) and the Concierge/Trip-Ideas saves (via `normalizeGoogleVerificationDetails`'s `googleVerification.lat/lng`) and `addHotelToTrip` (`meta.lat/lng`) **already persist** real coords. The **gap was `addSavedItemToTrip`** (saved → trip place): it now copies `displaySnapshot` coords via the normalizer into `details.lat/lng` + `coordinateSource:"saved_item"` **only when valid** (so `createTripFromSavedItem`, which composes it, inherits the fix). Note carryover (`details.userNote`) preserved. **`assignIdeaToDay` only PATCHes `{day_id}`** — server keeps `details`, so coords survive assignment (unchanged + asserted).
- **Read-side gate:** `MapFoldOut.mapsUrlOf` now validates persisted coords through the **same normalizer** before building a `?q=lat,lng` link — so out-of-range / null-island values from *any* write path are rejected at render. Honest map-ready list unchanged; **no plotted pins**.
- **Tests:** new `tests/itinerary-coordinates.test.mjs` (normalizer range/null-island/numeric-string/real-shapes + no geocode/goldenSpread/index; `addSavedItemToTrip` persists snapshot coords only when valid + note carryover; `assignIdeaToDay` preserves details; existing paths still persist; MapFoldOut validates on read). Updated 2 v2A map assertions to the normalizer. **Not run locally (node_modules absent); validated via CI `certify`.**
- **Flows still WITHOUT coordinates (honest):** items whose source had no coords (e.g. concierge ideas lacking `googleVerification`, saved snapshots without lat/lng, flights) — never fabricated. **v2C** (real plotted Trip Lens) ships only once enough placed items carry real coordinates.
- **Out of scope:** plotted pin map, Day/Idea lenses, route optimization, geocoding, providers, SQL.

### Explore regression fixes (current branch — post-Observatory)

Two Level 2 user-visible regressions fixed after PR #460 merged:

1. **Hotel compare-link dates (Google Travel surface):** `buildHotelCompareUrl` now uses the **`/travel/search?q=...&ts=...`** Google Travel hotel-search surface (the working surface), not the prior `/travel/hotels?checkin=...` form which did not reliably honor dates. The selected check-in/check-out are carried in the deterministic **`ts` protobuf param**, built by `buildGoogleTravelDatesParam` and **verified byte-for-byte against a real Google Travel URL** (2026-07-31 → 2026-08-05). The `ts` payload is purely date-derived (check-in, check-out, nights, occupancy=1 room, USD); opaque session params (`qs`/`ved`/`ap`) are intentionally NOT fabricated. Guest count is surfaced in the human-readable `q` text only (honest limitation — `ts` occupancy is a fixed 1-room block). `handleSubmit` takes a single `const snapshot = {...form}` so the compare link and search request always use the same dates. `hotel-explore-live.test.mjs`: 36 tests incl. byte-for-byte `ts` reproduction, two dynamic date ranges, named Hyatt/Chicago regression.

2. **Flight per-offer prices:** Duffel adapter already maps each offer's `total_amount` independently. The `_search_booking_link` is shared (same Google Flights query URL) but prices are per-offer. Fixed two pre-existing source-code test failures in `flights-ignav-live.test.mjs`:
